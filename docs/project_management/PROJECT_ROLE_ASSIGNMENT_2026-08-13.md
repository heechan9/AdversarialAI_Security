# 개발 프로세스 역할 분담 최종안

프로젝트: 자율운항선박 VLM·LLM 기반 AI 보안 프레임워크 구현  
기준일: 2026-08-13

이 문서는 2026-08-05 개정본에서 후보로 표시됐던 담당자까지 포함해 전원에게 책임 산출물을 부여하고, 현재 실제 진행상황을 반영한 팀 확정용 역할안이다.

## 운영 원칙

최희찬은 적대적 공격과 멀티모달 API 핵심개발에 집중한다. 김태희, 이재혁, 김기호는 각각 모델·시뮬레이터, 분석·시각화, 논문·발표 산출물을 병렬로 책임진다.

## 역할 경계와 인계

1. 최희찬이 공격 결과를 만든 뒤 김태희에게 시뮬레이터 입력을, 이재혁에게 분석 원자료를 전달한다.
2. 이재혁은 해석과 그래프를 김기호에게 전달한다.
3. 김기호는 전달받은 결과를 논문과 발표자료로 통합한다.
4. 각 담당자는 다른 담당자의 업무를 대신 완료하기보다 파일 위치, 입력 형식, 핵심 수치, 주의사항을 포함한 검증자료를 인계한다.

## 즉시 실행 체크리스트

### 최희찬

- [ ] FGSM 공식 산출물 선별·PR 정리
- [ ] BIM alpha·steps 후보와 근거 제시
- [ ] API billing 해결 후 정상 응답 1회 검증
- [ ] PGD 설계·구현 착수 조건 정리

### 김태희

- [ ] 시뮬레이터 입력 JSON/CSV 스키마 정의
- [ ] 직진·회피·정지 규칙과 충돌 판정 기준 작성
- [ ] FGSM 결과 1종으로 end-to-end 연결
- [ ] Collision Rate 결과 형식 확정

### 이재혁

- [ ] CNN과 MobileNet FGSM 비교표 정리
- [ ] epsilon별 Accuracy·ASR 그래프 작성
- [ ] DDG·Sailboat 취약성 해석 정리
- [ ] 논문 실험방법·결과 섹션 초안

### 김기호

- [ ] 2쪽 논문 목차·분량 배분
- [ ] FGSM·BIM·PGD·JSMA 관련 연구 조사
- [ ] 발표 PPT·포스터 공통 디자인 틀 작성
- [ ] 2분 데모 영상 스토리보드 작성

## 팀 운영 규칙

1. 담당자는 코드가 아니라 검증 가능한 산출물까지 책임진다.
2. 실험 수치에는 실행환경·모델 SHA·데이터 manifest·파라미터를 함께 남긴다.
3. Git 작업은 구현·실험, 결과·status·커밋 보고, 검토, 사용자 push, PR 재검인 순서로 진행한다.
4. 논문과 발표는 마지막에 몰아서 만들지 않고 현재 확보된 Clean·FGSM 결과부터 병렬 작성한다.
