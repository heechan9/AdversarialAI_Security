## 현수 입력: 확인된 포장 문제와 가능한 다음 단계

원 패킷의 selection은 고정 원본보다 끝 LF가 하나 많아 저장 보고서와
`selection_sha256`이 다르다. 같은 문제가 manifest와 도구 사본에도 있으나,
기존 cross-input 검사를 실제로 막는 항목은 selection의 바이트 해시다.
기존 도구의 검사를 완화하지 않고 고정 객체의 바이트를 새 준비 폴더에 만든다.
[보완 도구·명령·입력 목록·판정 기준](../../HYUNSU_CROSS_ONLY_HANDOFF_20261026.md)을 따른다.

PC `return-evidence(1).zip`과 Linux
`StageB_tensor_trace_evidence_20260927.zip`을 수신 측 보존 영역에서 확보했다.
원본 ZIP 해시는 각각 기존 공개 기록과 일치한다. 생성 실행 `native-trace`,
`trace-on`, `trace-off-02`의 5항목씩, **15개 NPZ 참조**의 해시·배치 형식·유한값·범위를
확인했다. 중복 행 99가 포함되므로 15개 독립 이미지/관측을 뜻하지 않는다.
같은 항목의 전처리 배치 해시는 세 실행에서 같다. 보고서의 평가 SHA는
`491b973`이고 모델/manifest/selection 해시가 연결된다.

PC 도구 해시는 b92ba8 보존 도구와 같다. Linux 보고서의 옛 도구 해시는
`98b67d1c19b459138872c7f834e1a7f682c1ecb56266d4182f714eb32a10e74e`로
다르며 원본 실행 출처로 그대로 둔다. 새 지원에서 사용할 b92ba8 도구 출처를
과거 Linux 실행에 소급 기재하지 않는다.

이는 **입력 인수 점검**이다. PC에서 만든 배열을 현수 환경에서 분류한 결과를
확보한 것이 아니며, 아래 상태를 새로 부여하지 않는다.

| 이번 지원의 판정 | 현재 확인 상태 |
|---|---|
| `INCOMPLETE` | 반환 자산 점검·cross-only 결과·명령·환경·로그 미확보 |
| `SELECTED_MATCH` | 부여하지 않음. 선택 범위/비교 대상/라벨·확률 범위를 확인한 반환이 필요 |
| `SELECTED_DIFFERENT` | 부여하지 않음. 동일 입력 검증 후 실제 차이표/보고서가 필요 |

보존 배열은 확보돼 있으므로 수신 측 원본 부재를 누락 사유로 쓰지 않는다.
현수의 접근권한·두 모델/781장 로컬 보유 여부는 확인되지 않았으며, 자산 점검이
없으면 `0/2 일치`처럼 실제 측정한 수치로 채우지 않는다. 명령은 최소 행 99를
원래 32장 배치로 분류하고, 확대해도 원 패킷의 4장·5항목까지다.

## 보고서에 반영할 문장

> 김태희의 고정 baseline CPU 인계 자료와 이재혁의 저장 근거 검토는 기존
> 통합 기록을 확인했고, 김기호의 10월 24일 발표 검토·리허설 보고를 연결했다.
> 현수의 후속 지원은 저장된 PC/Linux 공격 배열을 같은 입력으로 분류하는
> 선택 진단이며, 현재 반환 결과는 확인되지 않았다. 기존 연구 PC의 LOCAL_PASS와
> 외부 재실행 FAIL·원인 미확정은 함께 유지한다.

추가 안내가 필요할 때:

> 입력 패킷의 selection 바이트 해시 차이를 확인해 고정 원본 입력 준비를
> 보완했다. 이는 실행 준비 수정이며 새 공격·재학습·전체 시험셋 재실행이나
> 독립 재현 통과를 뜻하지 않는다.

기존 논문/10월 12일 수치와 10월 24일 단일 seed 후속 탐색 결과는 계속 분리한다.
이번 작업은 최종 원고·발표 자료에 위 문장이 실제 반영됐다고 인증하지 않는다.

- 원본 패킷 내부 해시 8개, 태희 내부 해시 22개, 재혁 준비본 3문서의 main

- 실제 원본 지원 패킷과 별도 `491b973` checkout으로 준비 명령을 실행해
  다섯 준비 파일을 확인했다. 새 selection 해시가 PC/Linux 세 생성 보고서의
  값과 일치했다. 모델 추론·현수 자산 점검·공식 Stage B 실행은 하지 않았다.

  원격 검사는 해당 PR의 실제 head에 연결된 Actions 결과를 참조한다.
- 기존 한 seed 연구·미실행 seed·외부 holdout/선박·장면 독립성·독립 모델 재현의
  한계는 해결되지 않았다. 입력 준비 성공이나 CPU CI를 성능 입증으로 쓰지 않는다.
