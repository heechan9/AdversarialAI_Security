# 클래스별 오류·실행 변동 검토 체크리스트

상태: 기존 감사 기능을 재사용하는 **검토 절차**. 새 공격·학습·독립 재현을
실행하지 않았으며 저장 예측, 정본 수치, 공식 승인 상태는 변경하지 않는다.
집단별 오류, 조건 통제, 변동 원인 분리라는 기초 분석 원칙의 적용이다.
외부 교육자료 원문은 포함하지 않는다.

2026-10-26 보완은 반도체 데이터 강의의 조건 비교·단계별 진단 관점을 기존
이미지 평가의 근거 연결에 적용한다. 반도체 공정 모델·장비 지표·강의 예시 성능을
이미지 모델의 결과로 옮긴 것이 아니며, 강의 슬라이드/그림을 재배포하지 않는다.

## 1. 클래스별 오류와 검토 우선순위

[클래스별 해석 규칙](PLYMOUTH_RESEARCH_ALIGNMENT.md)과
[ASR 입력 계약](ASR_INPUT_CONTRACT.md)의 계산·감사를 재사용한다.

- 입력 manifest·모델·코드·class map의 해시와 attack/epsilon/seed를 기록한다.
  동일 이미지 경로·라벨을 대조한 뒤 클래스별 N(전체), D(clean 정답),
  B=N-D(기존 오류), S(clean 정답→공격 오답)를 확인한다.
- 각 조건의 클래스별 N/D/S 합계가 전체 집계와 맞는지 확인한다.
  클래스별 ASR=S/D에서 D=0이면 classwise 함수는 None을 반환하며 보고서에는
  null/정의 불가로 표시한다. 전체 집계 함수 compute_untargeted_asr는 전체
  clean-correct 분모가 0일 때 ValueError를 발생시킨다. 어느 경우도 0% 성공률이
  아니다. 공격 후 정확도는 전체 N을 분모로 쓰므로 ASR과 혼용하지 않는다.
- 검토 순위를 정할 때 B와 S를 구분한다. S 내림차순으로 보는 오류 집중도와
  S/D로 보는 클래스 취약성은 목적이 다르다. 건수 순위만으로 희귀 클래스가
  안전하다고 판단하지 않는다. 표에는 n과 분모를 함께 남긴다.
- Pareto 형태의 누적 오류 표를 만들 경우 한 모델·한 공격 조건에서 중복 없는
  S만 합산하고, 총 S=0이면 누적 비율을 정의 불가로 둔다. 서로 다른 epsilon의
  같은 이미지를 독립 오류처럼 합치지 않는다. 이는 검토 우선순위이지 원인 입증이 아니다.
- CNN과 MobileNet의 clean-correct 집합은 다를 수 있다. 기존 ASR만으로 동일
  표본 우열을 주장하지 않는다. 공통 집합 분석은 사전에 고정한 별도 보조 분석이며
  현재 구현/실행 완료로 간주하지 않는다.

## 2. 공격·학습 효과와 환경 변동 분리

- 비교 전에 데이터/초기 모델/전처리/공격 norm·epsilon·step·budget/seed/
  선택 기준을 고정한다. 정상 오류, 공격 유발 오류, 방어 후 오류를 분리한다.
- 2026-10-26 확인 기준 학습/공격 코드의 Draft [#87 clean-only control](https://github.com/heechan9/AdversarialAI_Security/pull/87)은
  여전히 미병합이지만, 그 고정 SHA로 실행한 [10/24 matched CNN 저장 근거](../results/extensions/matched_cnn_20261024/README.md)는
  main에 있다. 두 학습군의 **seed 2026 한 쌍**은 `COMPLETED_NOT_INDEPENDENT_APPROVAL`이며,
  seeds 2027/2028은 미실행이다. 코드 병합 상태와 실제 저장 결과 수신 상태를 구분한다.
  기존 [저장 감사](../verification/matched_cnn_saved_audit.py)를 재사용하며 새 기능으로 세지 않는다.
  PGD7/PGD50 결과를 과거 FGSM 표와 합치거나 독립 재현 승인으로 승격하지 않는다.
  own-clean ASR 분모도 baseline 504 / clean-only 539 / mixed 540으로 다르다.
- [환경 추적 절차](STAGE_B_ORIGINAL_ENVIRONMENT.md)에 따라 환경·배열·예측을
  구분한다. 라이브러리, 하드웨어, numerical flags가 다른 실행의 예측 차이를
  공격 효과나 모델 개선으로 귀속하지 않는다. 한 사례의 라벨 일치가 전체 독립
  재현 PASS 또는 원인 확정을 뜻하지 않는다.
- 조건/seed 일부만 완료했거나 중단·ERROR가 있으면 완료/계획 건수를 함께
  표시한다. 2026-10-21 확인 기준 미병합 Draft [#86](https://github.com/heechan9/AdversarialAI_Security/pull/86)의
  중단 실행 감사가 보완하는 범위를 따로 확인한다. 남은 CSV나 파일 존재만으로
  완료를 판정하지 않으며 오류 실행을 성공률 분모에서 조용히 삭제하지 않는다.
- 차이가 있는 조건은 한 번에 한 요인씩 분리한 진단 후보로 기록한다. 다중
  조건을 바꿔 과거 라벨에 맞추거나 유리한 seed만 택하지 않는다. 탐색 후 수정한
  결과는 새 고정 검증 없이는 독립 성능 향상으로 주장하지 않는다.
  한 요인씩 확인하는 진단만으로 상호작용을 배제하거나 단일 원인을 입증하지 않는다.

## 3. 제출 주장 하나에 연결할 네 단계의 근거

다음은 새 판정 체계가 아니라 기존 감사·[불일치 이력](DISCREPANCY_LIFECYCLE.md)을
읽는 순서다. 각 단계에 **직접 확인 / 제출자 보고 / 미확인**을 적고,
앞 단계 통과를 뒤 단계 완료로 바꾸지 않는다.

| 단계 | 연결할 증거 | 이 단계만으로 말할 수 없는 것 |
|---|---|---|
| 입력 무결성 | 평가·도구 SHA를 각각 기록; manifest·모델·선택/배열 해시, 표본 순서·라벨, 전처리 | 파일 해시 일치만으로 모델 추론·예측 일치 또는 출처 인증 |
| 실행 | 실제 명령, OS/CPU/GPU·Python/TF/Keras, numerical flags 또는 unset, 시작/종료 시각·로그·종료코드, 수행자 | 명령 예시·CI PASS·제출 보고를 원본 실행 관찰로 바꾸기 |
| 출력 비교 | 정확한 비교 대상 SHA/run, 완료/계획 범위, 라벨 차이와 확률 차이 별도, 분자·분모·cohort·허용오차 | 저장 CSV 재계산 또는 선택 일치를 전체 781장 독립 재현 PASS로 확대 |
| 원인 가설 | 처음 확인한 차이의 단계, 통제한 비교축, 일치하지 않는 관측, 남은 대안과 다음 검증 | 환경 상관·일부 라벨 회복을 모든 불일치의 단일 원인으로 확정 |

- 환경 비교는 같은 이미지·모델·전처리·공격 조건을 고정하고, 저장 배열 교차
  분류라면 동일 배열 해시까지 대조한다. 불명확한 입력 차이는 환경 효과로 설명하지 않는다.
- 방어 비교는 같은 이미지/라벨·모델·epsilon의 쌍을 연결하되 무방어/전달/방어 인지
  조건을 명시한다. 학습군 비교는 같은 초기 모델과 기록된 학습 규약을 확인하고
  **서로 다른 최종 checkpoint**를 기록한다. 각 모델의 자체 경사 공격을 같은 공격
  배열이라고 부르지 않는다. 정상 오류·공격 유발 오류·새로 정답/오답이 된 사례를 분리한다.
- 10/26 수신 반영 초안 [#101의 고정 근거](https://github.com/heechan9/AdversarialAI_Security/blob/f65d0398a1967a2f3ed763f02de12f0405acb1eb/docs/reviews/20261026/final_submission_integration.md)는
  제출 JSON 783개 항목(모델 2개·이미지 781개)의 해시 정합성과
  `ASSETS_MATCH`, `model_inference_performed=false`를 기록한다. 현수 PC의
  자산을 새로 읽은 검사가 아니며, 선택 cross-only는 **INCOMPLETE**다.
  해당 Draft의 수신 기록과 main 병합 상태를 혼동하지 않는다.
- 기존 연구 PC `LOCAL_PASS`, 최초 외부 실행의 **16개 예측 셀·14장 불일치 FAIL**,
  원인 미확정은 함께 보존한다. [실행별 등록부](VERIFICATION_STATUS_REGISTRY.md)의
  상태나 허용오차를 이 체크리스트 작성만으로 변경하지 않는다.

## 검토 기록 양식

- source commit / manifest·모델·class map 해시 / 데이터 역할:
- 모델·공격·epsilon·seed / 전체·완료·보류 조건 수와 사유:
- 클래스별 N/D/B/S/ASR/공격 후 정확도 / 집계 일치 검사:
- 환경 차이 / 동일 조건 확인 / 관측한 차이 / 원인 미확인 항목:
- 증거 상태(정본·잠정·탐색) / 기존 감사 결과와 링크 / 다음 독립 검증:
- 단계별 직접 확인·제출자 보고·미확인 / 실제 명령·로그·종료코드 / 실행자·검토자:

작은 수정은 [팀 검토 절차](REVIEW_WORKFLOW.md)와
[영문 최소 재현·인계 양식](templates/evidence_handoff.md)에 연결한다.

Cp/Cpk·6시그마 등 제조 공정능력 지표를 분류 정확도에 붙이지 않는다.
오류 순위·상관만으로 실제 선박 사고나 시스템 수준 안전성을 입증하지 않는다.
