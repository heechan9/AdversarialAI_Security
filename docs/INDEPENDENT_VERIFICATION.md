# 독립 검증 (Independent Verification) — 작업 계획

Clean·FGSM 결과를 저장소의 기존 평가·감사 파이프라인 **바깥에서** 다시 계산해,
커밋된 수치와 일치하는지 확인하는 별도 검증 작업의 계획 문서다.

> **이 문서는 아직 결과가 아니라 계획이다.**
> 검증 수치는 하네스가 실행된 뒤 이 문서에 채워진다.

## 0. 불변 조건 (작업 전체에 적용)

이 작업은 다음을 **한 바이트도 수정하지 않는다.**

- `src/adversarial_ai/` 의 모델·공격·평가 코드
- `results/clean/` 의 canonical Clean 결과
- `results/attacks/provisional/` 의 FGSM 예비 결과
- `configs/` 의 실험 설정과 manifest

검증 산출물은 전부 신규 경로에만 쓴다. 기존 결과를 재생성하거나 대체하지 않으며,
불일치가 나오더라도 이 작업이 기존 파일을 고치지 않는다 — 불일치는 보고 대상이다.

## 1. 왜 "독립"인가

| 항목 | 저장소 기존 감사 | 이 독립 검증 |
| --- | --- | --- |
| 실행 주체 | `scripts/audit_research_evidence.py` (`adversarial_ai.audit`) | 별도 하네스 (신규 경로) |
| 코드 재사용 | 저장소 감사 모듈 | `adversarial_ai.*` 를 **임포트하지 않음** |
| 의존성 | pandas | Python 표준 라이브러리만 (A단계) |
| 산출물 | `results/audit/` | 신규 검증 결과 경로 |

기존 감사 모듈을 임포트하지 않는 것이 핵심이다. 같은 코드를 다시 돌리면
같은 버그를 다시 통과시킬 뿐이므로, 지표 재계산 로직을 처음부터 따로 구현한다.

## 2. 2단계 구조

### A단계 — 산출물 기반 독립 재계산 (바이너리 불필요)

커밋된 표본별 CSV에서 요약 지표를 처음부터 재도출하고 커밋된 요약값과 대조한다.
모델 `.h5` 와 781장 원본 이미지 없이 clean checkout에서 실행된다.

검증 항목:

| 항목 | 기존 감사 커버리지 |
| --- | --- |
| Clean 정답 수 · 정확도 | 있음 |
| FGSM robust accuracy · ASR · ASR 분모 | 있음 |
| L∞ 계약 (`L∞ ≤ ε + 1e-6`) · ε=0 대조조건 | 있음 |
| **Macro precision / recall / F1 재계산** | 없음 |
| **혼동행렬 CSV 재계산** | 없음 |
| **`linf_mean` 재계산** | 없음 |
| **확률 컬럼 argmax ↔ `predicted_index` 일치, 행 합 ≈ 1** | 없음 |
| **`fgsm_<model>.csv` 모델별 요약행 재계산** | 없음 |
| **Clean CSV ↔ FGSM 표본 CSV 행 순서·대상 파일 정합** | 위치 기반 비교만 |
| **manifest 781건 ↔ 결과 CSV 대상 파일 집합 대조** | 부분 |

마지막 두 항목이 필요한 이유: Clean CSV는 경로 구분자로 `/` 를,
FGSM 표본 CSV는 `\` 를 쓴다. 두 파일이 같은 781장을 같은 순서로 서술한다는 점을
경로 정규화 후 명시적으로 확인해야 한다.

ε 목록은 하드코딩하지 않고 커밋된 산출물에서 발견한다. 멘토가 승인할 ε가
현재 예비값(`0, 0.01, 0.03, 0.05`)과 달라져도 하네스를 수정할 필요가 없게 하기 위함이다.

### B단계 — 모델 재실행 (멘토 ε 승인 + 바이너리 확보 후)

`.h5` 모델을 직접 로드해 781장에 대한 예측과 FGSM 공격을 재실행하고,
커밋된 표본별 예측 자체를 재생성해 대조한다.

**선행 조건 (현재 미충족):**

- `models/cnn_baseline.h5`, `models/mobilenet_finetuned.h5` (및 필요 시 `mobilenet_stage1.h5`)
  — 저장소에 커밋돼 있지 않다 (`.gitignore`). 검증자에게 전달돼야 한다.
- `data/test` 781장 — 동일하게 미커밋.
- 전달된 바이너리의 SHA-256이 `results/*/**_metadata.json` 에 기록된 값과 일치해야 한다.
  (예: CNN `cb256b1a5d6f605d355334e4e8667257a2bfbd29e08836cc4114869bd7068701`)
- 멘토의 ε 범위 승인 — 승인 ε가 바뀌면 canonical FGSM 산출물 자체가 재생성되므로,
  그 이전에 B단계를 실행하면 대조 대상이 사라진다.

**허용오차 규약 (명세 확정 필요):**

TensorFlow/Keras forward pass는 하드웨어·연산 순서에 따라 비트 단위로 재현되지 않는다.
따라서 B단계는 "완전 일치"가 아니라 명시된 허용오차로 판정한다. 제안 규약:

| 대상 | 판정 기준 |
| --- | --- |
| 표본별 예측 라벨 | 100% 일치 |
| 정확도 · ASR | 절대차 ≤ 1e-6 |
| 표본별 확률값 | 절대차 ≤ 1e-5 (참고 기록, 판정에는 미사용) |
| L∞ | `≤ ε + 1e-6` (기존 계약과 동일) |

이 표는 제안값이며 확정 전까지 판정 기준으로 사용하지 않는다.
