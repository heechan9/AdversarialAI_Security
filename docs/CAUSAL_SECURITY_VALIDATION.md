# 인과·운영 보안 검증 계획

## 무엇을 입증했는지 구분하기

현재 clean 평가와 FGSM 실험은 고정된 이미지 표본에서 모델 정확도와 공격 취약성을 측정한다. 이는 특정 공격·모델·전처리 조건의 **실험 성능** 근거이며, 실제 선박에서 공격이나 사고를 예방했다는 인과효과 근거가 아니다. 방어기법을 추가한 뒤 수치가 달라져도 동일 공격조건과 비교군 없이 “보안위험을 감소시켰다”고 표현하지 않는다.

## 평가 층위

| 층위 | 답하는 질문 | 답하지 못하는 질문 |
| --- | --- | --- |
| Clean/attack benchmark | 알려진 표본·공격에서 얼마나 틀리는가 | 실제 공격 발생률·사고 감소 |
| 통제된 red-team 비교 | 같은 시나리오에서 방어 적용 전후 오류가 달라지는가 | 장기 운항 효과 |
| 그림자 운항 | 실제 입력 분포에서 경보와 인간 대응이 어떠한가 | 추천이 실제 판단을 바꾼 효과 |
| 제한적 전향 도입 | 방어 노출이 탐지·대응·안전지표를 개선하는가 | 검증하지 않은 선종·해역으로의 일반화 |

## 통제된 비교와 단계적 도입

- 방어 버전, 공격 예산, 표본, 모델, 전처리, seed와 평가 규칙을 사전에 고정한다.
- 가능하면 시나리오 또는 시간 블록 안에서 방어 노출 순서를 무작위화하고, 같은 조건의 무방어·기존방어 비교군을 둔다.
- 실제 운항 전 그림자 모드에서 경보는 기록하되 제어에는 연결하지 않는다.
- 단계적 도입 시 도입 전 추세와 아직 도입하지 않은 유사 선박·카메라의 추세를 확인하고, 모델·센서·운항절차의 동시 변경을 기록한다.
- 모든 자동조치는 인간 승인과 독립적인 안전장치를 유지한다.

## 선택적 라벨과 기저율

공격으로 판정되거나 사람이 검토한 표본만 정답이 생기면, 관측된 정밀도는 전체 운항 입력의 성능을 대표하지 않는다. 경보 표본뿐 아니라 무경보 표본을 확률 추출해 독립 검토하고, 검토 누락·판정 불일치를 보고한다. ASR의 clean-correct 분모와 전체 robust accuracy를 분리해서 표기한다.

공격·오탐의 기저율은 선종, 해역, 주야, 기상, 카메라와 데이터 출처에 따라 달라질 수 있다. 전체 평균만으로 공정성이나 안전성을 판단하지 않고 각 집단의 표본 수, clean 정확도, 공격 성공률, 오탐·미탐, 인간 검토 부담을 함께 보고한다. 하나의 공정성 지표만 만족한다고 모든 집단에 공정하다고 주장하지 않는다.

## 운영 판정 기준

배포 여부는 공격 성공률 하나가 아니라 clean 성능 저하, 오탐·미탐, 탐지 지연, 사람이 처리해야 할 경보량, 안전 우회 성공률을 함께 본다. 효과가 확인되지 않은 조건은 미검증 범위로 유지하며, 사고·공격 감소 주장은 충분한 전향 비교와 불확실성 구간이 있을 때만 한다.

## 근거 및 저작권 경계

이 문서는 인과추론과 알고리즘 감사의 일반 원칙을 프로젝트에 맞게 독자적으로 정리했다. 2026년 제3차 전문재판역량강화 프로그램의 김현철 강연 「경제학이 분석한 판사: 판사도 인간이다」에서 다룬 문제의식을 참고했지만 강의 녹취·슬라이드·도표·고유 사례를 재사용하지 않는다. 외부 자료를 추가할 때는 원 논문·공식 문서에 직접 연결하고 인용 범위와 라이선스를 확인한다.
