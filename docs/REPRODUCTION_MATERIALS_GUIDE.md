# 재현 자료 수령·검토 안내

이 안내는 PR #78의 `7145ed340b4e536ac9d50a1919cd805abb28d9f9` 트리를 기준으로 작성했다.
병커시유의 자료목록·기여 근거 안내에서 자료 종류, 실행/검토 SHA, 업무 배정/수행 구분 방식을 참고했다.
타 프로젝트의 데이터·모델·실험 결과·환경 설정은 가져오지 않았다.

## 어떤 자료를 확인했는가

| 자료 | 확인할 수 있는 범위 | 별도로 필요한 확인 |
|---|---|---|
| 공개 README·결과표·그래프 | 공개 주장과 집계 설명 | 비공개 CSV·모델의 원시 바이트 감사, 재추론 |
| `results/extensions/checkpoints/` | CPU 부분 체크포인트의 저장 정합성 | GPU 전체 완료와 구분 |
| `results/extensions/bim_gpu_20261004/` | 공개 BIM GPU 집계 | 원시 결과를 직접 받지 않았다면 원시 감사는 전달 보고로 기록 |
| 비공개 PGD `outputs/` | 원시 CSV, `run.json`, `parent-run.json` 확보 시 조건·해시·상속 감사 | 최신 상태·완료 여부, 환경·GPU 로그 검토 |
| 커넥터가 보여 준 CSV/JSON 텍스트 | 표시된 내용·행·필드 검토 | 원시 바이트 SHA256 검증으로 인정하지 않음 |
| 재현 ZIP 또는 폴더 사본 | 전달된 범위의 파일 검사 | 전체/부분 여부, ZIP 자체 해시와 내부 파일 해시를 각각 확인 |
| CI·Claude·Jules·작성자 보고 | 해당 작성자가 보고한 SHA·검사 결과 | 검토자의 직접 실행 및 외부 인간 승인과 구분 |

텍스트 사본, 공개 집계, 부분 폴더를 전체 원본 묶음이라고 부르지 않는다. 파일 업로드 시각도 실험 실행 시각을 대신하지 않는다.
원본은 보존하고 감사 보고서는 별도 위치에 저장한다. 공개 저장소에는 비공개 가중치·원자료·Drive 직접 링크·인증정보를 넣지 않는다.

## 수령 기록과 기존 감사기 재사용

기존 [검토 의견 양식](templates/review_feedback.csv)의 근거위치·미확인사항에 다음을 적는다.

- 자료 이름과 종류(원시 파일/ZIP/텍스트 표시/공개 집계), 전체 또는 부분 범위
- 실험 실행 SHA, 검토 코드의 정확한 SHA, run ID, 확인 일시
- 직접 계산한 해시와 전달받은 해시의 구분; 기준 해시의 출처
- 직접 읽음/직접 실행/전달 보고/미검증, 명령·exit code·검사 수·제한 사항

PGD 실행 소스는 `3294dcc5d6e34330be36b16d950d27e49e7a32ec`이며, 검토 브랜치의 SHA와 다르다.
이 기준 트리에 기록된 PGD는 13/16조건이다. 남은 Mean ε=.01/.03/.05, JSMA, 학습, 최종 평가는 완료로 간주하지 않는다.
`RUNNING` 파일만으로 현재 프로세스가 실행 중이라고 판단하지 않는다.

원시 PGD 폴더를 실제 확보한 검토자는 검토용 checkout에서 기존 감사기를 사용한다. 경로는 실제 수령 위치로 바꾼다.

```bash
git rev-parse HEAD
PYTHONPATH=src:. python verification/iterative_result_audit.py /path/to/received/pgd/outputs
```

`verification/stage_b_bundle.py`는 `rerun-report.json`과 `artifact_sha256` 형식의 **Stage B 묶음 전용**이다.
PGD의 `run.json`에 대신 적용하지 않는다. 5단계 통합 감사는 기존 `verification/full_extension_audit.py`를 사용하며 필요한 산출물이 없으면 미검증으로 남긴다.
감사 PASS는 파일 일관성의 범위로 한정한다. 모델 재추론, GPU 전체 재현, 논문 접수·채택 또는 독립 승인으로 확대하지 않는다.

## 검토 역할과 현재 보고의 한계

현수의 CPU 검토는 [현수 검토 묶음](HYUNSU_REVIEW_PACKET.md)을 사용한다. 업무 배정·안내문 작성은 실제 송신·실행·승인이 아니다.
구현, 자체검사, CI, AI 검토, 사람 검토, 병합을 각각 수행 근거와 함께 기록한다. 커밋 수나 저자 목록으로 기여 비율을 추정하지 않는다.

Jules는 `7145ed340b4e536ac9d50a1919cd805abb28d9f9`에서 CPU 검사 563 passed/0 skipped 및 확정 결함 없음으로 보고했다.
이는 **Jules의 실행 보고**이며 Codex의 직접 실행 기록이 아니다. 이 문서를 추가한 이후 head의 검사 결과로 재사용하지 않는다.
Codex가 읽은 `tests/test_recovery_preparation.py`에서 SHA·13조건·잔여 조건 가드는 노트북 문자열 검사이고,
노트북 구문 검사는 AST 검사다. 백업 바이트 보존·심볼릭 링크 거부 테스트와 구분해야 하며, 실제 GPU 복구 동작을 입증하지 않는다.
보고서의 개별 합성 반례를 독립 재현하려면 해당 명령·입력·로그가 추가로 필요하다. 비공개 CSV/모델 해시와 GPU 실행은 이 보고만으로 검증되지 않는다.
